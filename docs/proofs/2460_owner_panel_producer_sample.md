## Elaboration incidents (all root-caused, lessons in repo AGENTS)

- structInst line-break law: `{ f := v, ... }` continuation field
  lines must be indented at least to the `{` column; the earlier
  inline-box emission outdented continuation fields under
  `have hbm : (` and the parser reported `unexpected identifier;
  expected '}'` at the NEXT field.  Bisected with four layouts; the
  fix is structural - boxes live in defs, statements reference the
  defs (also removes 700-char statement lines).
- `Real.exp` / real-division box defs need `noncomputable def`
  (60 incidents, one per bump/phase box), and `rects2460` inherits it.
- arg paren law: `Real.cos (a + b) / 2` binds the division OUTSIDE
  cos - the oriented midpoint argument needs the double-wrapped
  `Real.cos ((a + b) / 2)`.
- simpa-delta vs rw-rfl: inside `simpa [bumpBox, ...]`, the by-block
  expected type has the box def unfolded, so `rw [hX0b]` leaves a
  defeq-but-not-rfl goal; fixed with an explicit intermediate
  `have h2 := le_trans hsup (le_of_eq hX0b)` outside the simpa.
- `rcases abs_le.mp h with a b` hit an unexplained parse break
  (`unexpected identifier; expected command` at the second pattern
  name); `obtain ⟨a, b⟩ := abs_le.mp h` is green - use obtain.
- Unconditional emission of `hm0 : 0 <= m` for all-negative mods
  would fail norm_num; sign-side haves are now emitted per family
  sign.  (The sin-side midpoint lemma `hsli` was also missing in the
  first cut - the phase door needs both cos and sin boxes.)
