Negative-numerator shape class

The first generation pass stopped at panel 004 coefficient 31 with a
negative numerator: the chunk interface of record 2630 is
nonnegative-only, and 176 of the 180 panels carry at least one
negative numerator (2477 negative panel-coefficient pairs, about 42
percent), so the negative shape is the common case, not a corner.
Canonical Fractions keep denominators positive, so only numerators
carry the sign. The generator now emits sign-magnitude certificates:
magnitude blocks stay in Nat and the sign is pinned in Z by
`(-1 : Z) * (blockValue8 .. : Nat) = -M`. A four-shape probe settled
the form: a bare cast goal `((blockValue8 .. : Nat) : Z) = -M` is
FALSE (left side positive), and `(-(x : Nat) : Z)` elaborates Neg at
Nat (truncating), so the multiplier form is required. Panel 002
regeneration stays byte-identical to the committed module (probe
kept as a regression gate), and panel 004 with 98 negative-shape
theorems compiles in 33.1 s - the negative shape costs nothing
against the 32.5 s nonnegative baseline.

Instrument incidents

Two tooling defects were caught by the file-level acceptance and are
the reason that acceptance exists:

1. Lake 5.0 has no `-j` option; the first batch command died with
   "unknown short option '-j'" after the generation phase, and the
   wrapper still reported exit 0 (the known wsl.exe exit-code
   mirage). Compilation had not run at all.
2. The re-run batched with `seq $start $((start+7)) 179` - but
   three-argument seq reads the middle value as STEP, so each batch
   compiled a stride sequence and left 98 panels uncompiled while
   every batch reported OK. The backfill script
   `build-logs/backfill_2632_batch.sh` compiles the file-tested
   missing set in sub-batches of 8; 13 sub-batches, ERRORS=0.

Law (AGENTS 2cb): batch compilation acceptance is the count of
persisted oleans tested per file, never the runner exit code and
never a batch-level OK line.
