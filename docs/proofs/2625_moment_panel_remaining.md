The negative-center shape class

The first validation attempt failed wholesale on the first negative-
center panel and exposed a parameterization coverage gap: record 2622
validated panels 090-099, whose centers are all positive, so the
negative-center shape class had never been compiled. Two independent
emitted-term defects, both invisible to every Python-side gate, failed
the class:

1. The charge theorem's `simpa only` cast-push list omitted
   Rat.cast_neg. For a negative center, cast_div leaves the residual
   (Rat.cast (-179)) / 200, which no listed lemma reduces, and the
   simplifier output cannot match the target shape. Rat.cast_neg was
   already used unconditionally in the sibling table module - the
   omission was per-site.

2. The error-bound theorem's interval endpoints emitted (-9 / 10),
   which elaborates as (Neg 9) / 10, while the norm_num products inside
   the proof carry Neg (9 / 10). The two Real shapes are not
   Eq.mp-compatible at the closing `exact`, although they are equal
   rationals.

Both are fixed in the generator with sign-conditional emission: only
negative centers add Rat.cast_neg to the simplifier list and emit
-(p / q) endpoints, so the committed positive-center panels regenerate
byte-identically and the hash-checked 2622 parent stays untouched. The
four shape-class boundary panels (000 and 089 negative, 100 and 179
positive) were compiled individually before the batch rerun. The
general law is recorded in AGENTS 2ca: a parameterized generator must
compile one instance per shape class, not just per numeric range.
