# Route map

This directory contains the current high-level route analysis: architecture,
route selection, and external-interface boundaries. Concrete proof bricks,
Lean implementation records, and candidate-carrier studies remain in
[`../proofs/`](../proofs/).

Map filenames use consecutive `001_`, `002_`, ... reading-order prefixes.
Their document titles retain the original proof-record identifiers for source
traceability.

## Mandatory preflight

For each new substantive proof brick, Lean theorem, carrier-family design, or
numerical investigation, use this layered check:

1. Always read this index and binding route ruling
   [`003`](003_b1_b5_minimal_exit_route_selection.md).
2. Read [`004`](004_endpoint_literature_interface_audit.md) when the work
   touches C3, endpoint certificates, or an external endpoint source.
3. Read [`001`](001_first_cut_window_architecture.md) and
   [`002`](002_one_shot_rh_route_verdict.md) when the work uses the
   ROOT-window local base, `gamma + alpha/beta + delta`, paper-scale Toeplitz
   work, or a quantifier boundary.
4. Read all four current records in order when opening a new proof campaign or
   after any change under `docs/map/`.

The new work must name its healthy-`CompactLog`, B5-shaped consumer; otherwise
it is out of scope and must not start.

## Live update rule

This is a living route map. During proof work, update the affected map record
immediately when new evidence changes route selection, brick status, owner,
quantifier, consumer, a no-go ruling, or an endpoint supplier; do not wait for
a campaign or batched build to end. Cite the evidence and label the result as
formal, literature-backed, or a project candidate.

If an update changes binding route authority or current status, synchronize
the repository `README` and `RH_MAINLINE_FREEZE.md` in the same change. Keep raw or
unresolved numerical observations in [`../proofs/`](../proofs/); they do not
by themselves change a map conclusion. A new route-level record receives the
next sequential `00N_` filename.
